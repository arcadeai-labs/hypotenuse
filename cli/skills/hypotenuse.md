# hypotenuse

`hypotenuse` is the command-line client for a [Hypotenuse](https://github.com/arcadeai-labs/hypotenuse)
server. It calls the same HTTP actions the dashboard does, as the person who signed it in.

## Conventions

- **stdout is data, stderr is for people.** Pass `--json` (`-j`) to get the action's named object
  (`{ projects, pagination }`, `{ project }`, …) on stdout with no color. Parse that, never the
  tables.
- A non-zero exit code means the command failed; the reason is on stderr.
- Lists take `--page` and `--limit` (default 25) and answer a
  `pagination: { page, limit, total, pages }` envelope.
- Organization-scoped commands act on `--org <id|slug>`, else `HYPOTENUSE_ORG`, else the organization
  chosen with `hypotenuse org use`, else the person's only organization.
- Project-scoped commands act on `--project <id|slug>`, else `HYPOTENUSE_PROJECT`, else the project
  chosen with `hypotenuse project use`, else the person's only project.
- An explicit `--org` widens `project list`, `invite list`, and `audit list` to the whole organization.
- The server is `--url`, else `HYPOTENUSE_URL`, else wherever `login` last signed in.
- `HYPOTENUSE_NO_UPDATE_CHECK=1` turns off the background update notice.

## Commands

| Command | Does |
|---|---|
| `hypotenuse login [--device] [--name <name>]` | Sign in through the dashboard. A person must approve in a browser; `--device` prints a code to type at `/cli/activate` on any device. Never ask for a password. |
| `hypotenuse logout` | Revoke this CLI's sign-in on the server and forget it locally. |
| `hypotenuse whoami` | Who this CLI is signed in as, on which server. |
| `hypotenuse org list\|view\|use\|create\|edit\|delete\|members\|member` | The caller's organizations. `use <id\|slug>` selects one. `create --name`; `edit [org] --name --slug` and `delete <org> --yes` (owner). `members` lists the selected organization's members and roles; `member set-role <userId> owner\|member` and `member remove <userId>` (owner; your own id to leave). |
| `hypotenuse project list\|view\|use\|create\|edit\|settings\|delete` | The caller's projects. `create --name` makes one in the selected organization. `edit [project] --name` and `delete <project> --yes` (admin). `settings [project]` shows where its sandbox jobs run (`effectiveSandbox`, with `null` fields meaning the deployment's default); with `--sandbox-provider <name>`, `--sandbox-image <image>`, `--sandbox-concurrency <n>`, `--sandbox-max-duration <30m\|2h\|seconds>` (or each one's `--no-*` for the default) it changes them (admin). `use <id\|slug>` selects the project later commands act on. |
| `hypotenuse member list\|add\|remove` | The selected project's members. `add --email` adds a member of the project's organization; `remove <userId>` (admin). |
| `hypotenuse invite list\|pending\|create\|accept\|reject` | Invitations. `create --email [--tag <id>]` invites into the selected project (admin); `--organization-only` invites into the organization (owner). `pending` lists invites addressed to you; `accept`/`reject <inviteId>`. |
| `hypotenuse tag list\|create\|edit\|delete\|assign\|remove` | Permission tags. `create <name>`, `edit <tagId> --name`, `delete <tagId>`, `assign <tagId> --user <userId>`, `remove <tagId> --user <userId>` (admin). The `admin` tag is reserved. |
| `hypotenuse model connection list\|view\|add\|edit\|rotate\|test\|models\|remove` | The project's model providers (admin to change). `add --name --provider anthropic\|openai\|gateway\|openai-compatible [--base-url]` and `rotate <connection>` read the key from `--api-key-stdin` or `--api-key-env <NAME>` (or a hidden prompt on a terminal) — never put a key on the command line. `test <connection>` probes it and exits 1 when the probe fails; `models <connection>` lists model ids. A connection is named by id or name. The key is never shown, only its last four. |
| `hypotenuse model alias list\|set\|remove` | The model names bots use. `default` and `fast` are required before any bot runs; `list` reports `missingRequired`. `set <name> --connection <id\|name> --model <modelId> [--max-output-tokens <n>] [--temperature <t>] [--kind language\|embedding]` creates the alias or changes the one of that name (admin); `--kind embedding` is only for the alias named `embedding`, the model memory embeds with, and a kind never changes. `remove` is refused while a bot names it. |
| `hypotenuse bot list\|view\|create\|edit\|delete` | The project's bots. `create --name <name> --persona-file <persona.md>` plus any of `--slug`, `--description`, `--display-name`, `--avatar-file <png\|jpeg>`, `--model <alias>`, `--fast-model <alias>`, `--read <tags>`, `--write <tags>` (comma-separated tag names; `""` or `*` is every member), `--help-tag <tag>` / `--no-help-tag`, `--budget <usd>` / `--no-budget`, `--max-steps <n>`, `--channel-half-life <days>` / `--project-half-life <days>` (1–3650; how fast its memory fades), `--approver-tag <tag>` / `--no-approver-tag` (who besides its writers decides its approvals), `--approval-ttl <30m\|24h\|7d\|seconds>` (how long an approval waits; 1m–30d, default 24h), `--prompt-budget <tokens>` (the system prompt's budget, default 8000), `--max-agent-sections <n>` (sections the bot may add itself, default 10), `--code` / `--no-code` (whether it may run programs with `run_code`), `--code-timeout <s>` / `--code-memory <MiB>` / `--code-host-calls <n>` (its own code limits, only lower than the deployment's; together they replace its limits) or `--no-code-limits`, `--enable` / `--disable`. The persona is the bot's prompt's `identity` section. `edit <bot>` changes only the flags given (`--no-avatar` removes the avatar; `--auto-bind public,private,dm\|none` sets which channels it starts listening in by itself when invited; `--participant-rate-limit <n>` / `--channel-rate-limit <n>` cap messages a minute from one platform person or one channel; `--sandbox off\|approve\|allow` sets whether it may hand code work to sandbox jobs, `approve` making each wait for a person; `--sandbox-token-budget <tokens>` / `--no-sandbox-token-budget` caps one job's model tokens); `delete <bot> --yes`. A bot is named by id or slug; `view` says whether you can change it (`standing.canWrite`). |
| `hypotenuse bot callback-secret <bot> [--yes]` | Create the secret a bot signs its API callbacks with and print it once on stdout (write access). It is never shown again; replacing an existing one needs `--yes` and stops callbacks signed with the old one. |
| `hypotenuse prompt list\|view\|versions\|add\|edit\|revert\|remove\|preview` | The sections a bot's system prompt is assembled from. `list [--bot <bot>] [--deleted]` shows a bot's sections, or with no `--bot` the project's (every bot includes them). A section is named by id, or by key with `--bot` (no `--bot`: a project section's key). `view <section>`; `versions <section>` says who wrote each version — a person, the bot itself (with the conversation), a revert, or the seed. `add --title <t> [--bot <bot>] [--key <k>] [--body <text\|-> \| --body-file <path>] [--always\|--contextual] [--keyword <w>]… [--agent-editable] [--position <n>] [--note <why>]` (a bot section needs its write access; a project section needs admin). `edit <section>` takes the same flags plus `--no-keyword`, `--no-agent-editable`, and `--base <version>` (refused if it changed since); a text change is a new version. `revert <section> --to <version>` puts an old version's text back as a new version — how to undo a bot's own edit. `remove <section> --yes` (not a bot's `identity`). `preview --bot <bot> [--message <text>] [--conversation <id>] [--sections]` prints the exact system prompt, its sha256, the context terms, the sections included and those dropped for the token budget. A change that would push the always-included prompt over the bot's budget is refused. |
| `hypotenuse goal list\|view\|add\|edit\|remove` | What a bot works toward. `list --bot <bot> [--status active\|achieved\|dropped]`; `view <goal>`; `add --bot <bot> --title <t> [--description <d>] [--priority high\|medium\|low] [--notes <n>] [--review-every <12h\|7d>]`; `edit <goal>` with the same flags plus `--status` and `--no-review-every`; `remove <goal> --yes`. Active goals are in the bot's prompt; the bot may change only a goal's status and notes. Changing needs write access to the bot. |
| `hypotenuse skill list\|view\|versions\|add\|edit\|remove\|attach\|detach` | The project's skills: procedures bots follow with `use_skill`, or a person runs by starting a message with `/<name> args…`. `list [--bot <bot>]` (with `--bot`, the skills attached to it and the version each uses); `view <skill>` (id or name); `versions <skill>`; `add <name> --description <d> --body <text\|-> \| --body-file <path> [--arg <name\|name!\|name=default>]… [--read <tags>] [--write <tags>]` (`name!` is required; the template uses `$1`, `$ARGUMENTS`, `$<name>`); `edit <skill>` with the same flags plus `--name` and `--no-arg` (a new description, arguments, or body is a new version); `remove <skill> --yes`; `attach <skill> --bot <bot> [--pin <version>]` and `detach <skill> --bot <bot>` (write access to the bot, read access to the skill). |
| `hypotenuse bot tools list\|add\|remove` | The MCP servers a bot may use. `list <bot>` shows each server's allowlist and read-only setting plus the bot's `capabilities` summary. `add <bot> <server> [--allow <pattern>]… [--no-allow] [--auto-allow-read-only\|--no-auto-allow-read-only]` binds a server or changes its settings (each `--allow` is `server/tool`, `server/*`, `*/tool`, a tool name, or `/regex/`, and the list replaces the old one; `--no-allow` clears it so every call asks); `remove <bot> <server>`. Changing needs write access to the bot. |
| `hypotenuse mcp-server list\|view\|add\|edit\|test\|refresh\|match\|sign-in\|remove` | The project's shared MCP servers (admin to change; a server is named by id or name). `add <name> --endpoint <url>` (not `--url`, which names the Hypotenuse server) with `--header "Name: value"` (repeatable) or `--headers-stdin`, `--bearer-stdin` / `--bearer-env <NAME>`, or `--oauth [--client-id <id> --client-secret-stdin\|--client-secret-env <NAME>]`; the auth mode follows from those flags (or `--auth none\|headers\|bearer\|oauth`), and only one flag may read stdin. Never put a credential on the command line. `--oauth` and `sign-in <server>` print the URL an admin opens to sign the project in (`authorizationUrl` under `--json`). `view <server>` lists its `tools`; `test` / `refresh <server>` reconnect and re-list, exiting 1 when it does not answer (`ok`, `error`). `edit <server>` takes the same flags plus `--name`, `--timeout-ms <ms>` / `--default-timeout`, `--enable` / `--disable`. `match <server> --pattern <p>…` shows what each pattern allows and what still asks (`gated`). `remove <server> --yes` takes it from every bot. Answers carry header names, a bearer's last four, and `signedIn`, never a secret. |
| `hypotenuse conversation create\|message\|list\|view\|cancel\|follow` | Talk to a bot over the API channel, or in a dashboard chat. `create --bot <id\|slug> --text <text> [--channel <key>] [--callback-url <url>] [--request-id <id>] [--title <t>] [--follow]` starts one; `create --web [--fresh]` starts it in the bot's dashboard chat instead (`--fresh`: a new scratch channel whose memory is empty; no `--channel` or `--callback-url`). `message <id> --text <text> [--queue] [--request-id <id>] [--follow]` sends into one (`--queue` waits for the bot's current turn). `--text -` reads standard input. `list [--bot] [--state working\|hibernating\|waiting\|ended]`, `view <id>`, `cancel <id>`. `follow <id> [--since <seq>] [--interval <s>]` prints the transcript and polls until the conversation stops working, then prints its state; it exits 1 when the conversation failed. On a terminal it also shows the bot's text as it is written, replaced by the finished message; piped output is only the finished lines. With `--json`, following prints one JSON object per line: each entry, then `{ conversation }`. A `--request-id` makes a retry safe. |
| `hypotenuse installation manifest\|connect\|test\|list\|view\|disconnect` | A bot's platform apps (write access to the bot to change). `manifest --bot <bot> [--type webhook] [--workspace <id>]` creates a pending installation and prints the manifest and the **events URL** the platform delivers to (`urls.events` under `--json`) — shown once; asking again mints a new URL. `connect --bot <bot> [--type] [--workspace] --delivery-url <url> [--bot-user-id <id>]` reads the signing secret from `--signing-secret-stdin` or `--signing-secret-env <NAME>` (or a hidden prompt) — never put it on the command line — and makes it active. `test <id>` probes it and exits 1 when it does not work (`ok`, `error`). `list --bot <bot>`, `view <id>` (with what the platform can show), `disconnect <id> --yes` (channels and conversations stay). Credentials are never shown. |
| `hypotenuse slack create\|connect\|install` | A bot's own Slack app (write access to the bot). `create --bot <bot> [--workspace <id>]` creates it from the bot's manifest with an app configuration token read from `--config-token-stdin` or `--config-token-env <NAME>` (used once, never stored) and leaves a pending installation. `connect --bot <bot> --client-id <id> [--app-id <id>] [--workspace <id>]` connects an app made from `installation manifest --type slack`, secrets from `--client-secret-env`, `--signing-secret-env`, and optionally `--bot-token-env` (a bot token activates it at once). `install <id>` prints the link a person opens to install the app into the workspace (once, ten minutes); check it afterwards with `installation test <id>`. |
| `hypotenuse pylon setup\|connect\|settings` | A bot on a Pylon support queue. `setup --bot <bot>` mints the installation and prints what a Pylon admin creates: an API token with its own identity, a webhook to the printed URL (shown once), and four Triggers with the body each sends. `connect --bot <bot> --region us\|eu --name <token's name>` connects it, the token from `--token-env` and the webhook secret from `--webhook-secret-env` (or a hidden prompt); Pylon is asked who the token is at once. `settings --bot <bot>` (project admins) sets `--policy never\|approve\|auto-on-low-risk` (whether the bot may reply to customers; `never` by default), `--auto-triage`, `--mention`, `--assignment` (`on\|off`), `--tags` and `--teams` (comma-separated, `""` for any), and `--legacy-signature`. |
| `hypotenuse linear link\|connect\|install` | A bot's own Linear app (write access to the bot). `link --bot <bot>` mints the installation and prints the pre-filled link a Linear workspace admin opens to create the app (its webhook URL shown once). `connect --bot <bot> --client-id <id>` connects it, secrets from `--client-secret-env` and `--webhook-secret-env` (or a hidden prompt); it stays pending until installed. `install <id>` prints the link that installs the app into the workspace with `actor=app` (once, ten minutes); check it afterwards with `installation test <id>`. |
| `hypotenuse channel list\|view` | Platform channels the project's bots hear from. `list [--bot <bot>] [--type <platform>]` (with `--bot`, each row carries the bot's `binding` or `null`); `view <id>` with the bindings of bots you can read. |
| `hypotenuse binding list\|create\|edit\|delete` | Where a bot listens (write access to the bot to change). `list --bot <bot>`; `create --bot <bot> --channel <id> [--mode mentions\|all\|dm] [--delivery steer\|queue] [--approval-policy dashboard\|participants\|listed] [--approver <platformUserId>]… [--allow-promotion] [--allow-shared] [--confirm-audience]` — a private channel is refused without `--confirm-audience` (everyone who can read the bot will read that channel's conversations and memory), a shared one without `--allow-shared`; `edit <id>` takes the same settings plus `--no-approvers`, `--no-allow-promotion`, `--no-allow-shared`, `--enable` / `--disable`; `delete <id> --yes`. |
| `hypotenuse approval list\|view\|approve\|deny` | Tool calls bots wait on. `list [--status pending\|approved\|denied\|expired\|consumed] [--bot <bot>] [--conversation <id>]` (each row says `canDecide`); `view <id>`; `approve <id> [--always] [--note <text>]` runs exactly that call once (`--always` also allowlists its `server/tool` for the bot); `deny <id> [--note <text>]` (the bot reads the note). Deciding needs write access to the bot or its approver tag; it is recorded as decided via `cli`. |
| `hypotenuse help-request list\|view\|answer\|cancel` | The help inbox: questions bots escalated to the team. (Not `help`: `--help` on any command shows its options.) `list [--status pending\|answered\|expired\|cancelled] [--bot <bot>]` (each row says `canAnswer`); `view <id>` (`standing.canAnswer`, `standing.canCancel`); `answer <id> --text <text\|->` — the bot reads "Answer from <you>: …" and carries on (its help tag's holders, admins, and its writers); `cancel <id>` withdraws it (write access to the bot). |
| `hypotenuse code-run list\|view` | Programs a bot ran in code mode. `list --conversation <id>` (newest first: status, first line, host calls, outcome); `view <id>` prints the program, its result or error, its console, every host call with how the gate let it through, and the approvals a paused one waits on. Never its saved continuation. Needs read access to the bot. |
| `hypotenuse sandbox list\|view\|events\|cancel\|answer` | Code work bots handed to a coding agent in a sandbox. `list [--bot <bot>] [--conversation <id>] [--status pending\|provisioning\|running\|awaiting_input\|succeeded\|failed\|cancelled\|timed_out\|expired]` (newest first, with token usage); `view <jobId>` prints its task, status, what the agent reported, closing text, artifacts, questions, messages, and sandboxes (`canWrite`); `events <jobId> [--after <seq>]` is its transcript, oldest first; `cancel <jobId>` stops it (a pending job at once, a running one within a heartbeat); `answer <jobId> <questionId> <answer\|->` answers an agent's question (a question sent to the team is answered in `help-request`). Needs read access to the bot; cancel and answer need write access. |
| `hypotenuse large-result view <lr_id> [--offset <n>] [--limit <n>] [--all]` | A tool result too long for the transcript (`lr_<id>` or its number): one page, or `--all` of it; `page.nextOffset` is where the next page starts. Needs read access to the bot. |
| `hypotenuse memory search\|list\|view\|versions\|channels\|write\|forget\|pin\|promote\|reindex` | What bots remember. Without `--channel <channelId>` a command acts on project memory (every bot shares it); with it, on that channel's memory, which every bot working in the channel shares (`channels` lists the channels you can read, with their bots). `search <query> [--scope project\|channel\|both] [--path <prefix>] [--limit <n>]` ranks as a bot does (`mode` says `hybrid` or `keyword`); `list [--scope …] [--path <prefix>] [--forgotten]` reports each document's `decay` and the `index`; `view <path> [--version-id <id>]` and `versions <path>` read a document and its history. `write <path> --text <text\|-> [--description <d>] [--note <why>] [--base <versionId>]` saves a new version (`--base` refuses it if the document changed since); `forget <path> [--reason <r>]`; `pin <path> [--unpin]`; `promote <path> --channel <id> [--to <path>] [--version-id <id>]` copies channel memory into project memory; `reindex` re-embeds after the embedding model changes. Project memory: members read, admins change; channel memory follows the read and write access of the bots working in the channel (any one of them is enough); promote and reindex need admin. |
| `hypotenuse participant list\|view` | People on platforms who have written to the project's bots — not Hypotenuse users, never linked to one. `list [--type <platform>] [--query <name>]`, `view <id>`. |
| `hypotenuse event list\|view` | Every platform delivery the bots received and what processing made of it (admin). `list [--status pending\|processed\|ignored\|failed] [--outcome <prefix>] [--installation <id>]`; `view <id>` prints the payload as received. |
| `hypotenuse audit list [--since 7d] [--until <time>] [--action tag:edit] [--actor-type user] [--target-type tag]` | Who changed what, newest first: the selected project's log (admin), or with `--org` the organization's (owner), narrowed by an explicit `--project`. Times are ISO-8601, epoch ms, or `7d` / `12h` / `30m`. |
| `hypotenuse check-update` | Whether a newer release exists, and its changelog. |
| `hypotenuse upgrade [--major]` | Upgrade by whichever method installed it. A new major version needs `--major`. |
