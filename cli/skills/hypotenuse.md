# hypotenuse

`hypotenuse` is the command-line client for a [Hypotenuse](https://github.com/arcadeai-labs/hypotenuse)
server. It calls the same HTTP actions the dashboard does, as the person who signed it in.

## Conventions

- **stdout is data, stderr is for people.** Pass `--json` (`-j`) to get the action's named object
  (`{ projects, pagination }`, `{ project }`, …) on stdout with no color. Parse that, never the
  tables.
- A non-zero exit code means the command failed; the reason is on stderr.
- Lists take `--page` and `--limit` (default 25) and answer a
  `pagination: { page, limit, total, pages }` envelope.
- Organization-scoped commands act on `--org <id|slug>`, else `HYPOTENUSE_ORG`, else the organization
  chosen with `hypotenuse org use`, else the person's only organization.
- Project-scoped commands act on `--project <id|slug>`, else `HYPOTENUSE_PROJECT`, else the project
  chosen with `hypotenuse project use`, else the person's only project.
- An explicit `--org` widens `project list`, `invite list`, and `audit list` to the whole organization.
- The server is `--url`, else `HYPOTENUSE_URL`, else wherever `login` last signed in.
- `HYPOTENUSE_NO_UPDATE_CHECK=1` turns off the background update notice.

## Commands

| Command | Does |
|---|---|
| `hypotenuse login [--device] [--name <name>]` | Sign in through the dashboard. A person must approve in a browser; `--device` prints a code to type at `/cli/activate` on any device. Never ask for a password. |
| `hypotenuse logout` | Revoke this CLI's sign-in on the server and forget it locally. |
| `hypotenuse whoami` | Who this CLI is signed in as, on which server. |
| `hypotenuse org list\|view\|use\|create\|edit\|delete\|members\|member` | The caller's organizations. `use <id\|slug>` selects one. `create --name`; `edit [org] --name --slug` and `delete <org> --yes` (owner). `members` lists the selected organization's members and roles; `member set-role <userId> owner\|member` and `member remove <userId>` (owner; your own id to leave). |
| `hypotenuse project list\|view\|use\|create\|edit\|delete` | The caller's projects. `create --name` makes one in the selected organization. `edit [project] --name` and `delete <project> --yes` (admin). `use <id\|slug>` selects the project later commands act on. |
| `hypotenuse member list\|add\|remove` | The selected project's members. `add --email` adds a member of the project's organization; `remove <userId>` (admin). |
| `hypotenuse invite list\|pending\|create\|accept\|reject` | Invitations. `create --email [--tag <id>]` invites into the selected project (admin); `--organization-only` invites into the organization (owner). `pending` lists invites addressed to you; `accept`/`reject <inviteId>`. |
| `hypotenuse tag list\|create\|edit\|delete\|assign\|remove` | Permission tags. `create <name>`, `edit <tagId> --name`, `delete <tagId>`, `assign <tagId> --user <userId>`, `remove <tagId> --user <userId>` (admin). The `admin` tag is reserved. |
| `hypotenuse model connection list\|view\|add\|edit\|rotate\|test\|models\|remove` | The project's model providers (admin to change). `add --name --provider anthropic\|openai\|gateway\|openai-compatible [--base-url]` and `rotate <connection>` read the key from `--api-key-stdin` or `--api-key-env <NAME>` (or a hidden prompt on a terminal) — never put a key on the command line. `test <connection>` probes it and exits 1 when the probe fails; `models <connection>` lists model ids. A connection is named by id or name. The key is never shown, only its last four. |
| `hypotenuse model alias list\|set\|remove` | The model names bots use. `default` and `fast` are required before any bot runs; `list` reports `missingRequired`. `set <name> --connection <id\|name> --model <modelId> [--max-output-tokens <n>] [--temperature <t>] [--kind language\|embedding]` creates the alias or changes the one of that name (admin); `--kind embedding` is only for the alias named `embedding`, the model memory embeds with, and a kind never changes. `remove` is refused while a bot names it. |
| `hypotenuse bot list\|view\|create\|edit\|delete` | The project's bots. `create --name <name> --persona-file <persona.md>` plus any of `--slug`, `--description`, `--display-name`, `--avatar-file <png\|jpeg>`, `--model <alias>`, `--fast-model <alias>`, `--read <tags>`, `--write <tags>` (comma-separated tag names; `""` or `*` is every member), `--help-tag <tag>` / `--no-help-tag`, `--budget <usd>` / `--no-budget`, `--max-steps <n>`, `--channel-half-life <days>` / `--project-half-life <days>` (1–3650; how fast its memory fades), `--approver-tag <tag>` / `--no-approver-tag` (who besides its writers decides its approvals), `--approval-ttl <30m\|24h\|7d\|seconds>` (how long an approval waits; 1m–30d, default 24h), `--enable` / `--disable`. `edit <bot>` changes only the flags given (`--no-avatar` removes the avatar); `delete <bot> --yes`. A bot is named by id or slug; `view` says whether you can change it (`standing.canWrite`). |
| `hypotenuse bot callback-secret <bot> [--yes]` | Create the secret a bot signs its API callbacks with and print it once on stdout (write access). It is never shown again; replacing an existing one needs `--yes` and stops callbacks signed with the old one. |
| `hypotenuse bot tools list\|add\|remove` | The MCP servers a bot may use. `list <bot>` shows each server's allowlist and read-only setting plus the bot's `capabilities` summary. `add <bot> <server> [--allow <pattern>]… [--no-allow] [--auto-allow-read-only\|--no-auto-allow-read-only]` binds a server or changes its settings (each `--allow` is `server/tool`, `server/*`, `*/tool`, a tool name, or `/regex/`, and the list replaces the old one; `--no-allow` clears it so every call asks); `remove <bot> <server>`. Changing needs write access to the bot. |
| `hypotenuse mcp-server list\|view\|add\|edit\|test\|refresh\|match\|sign-in\|remove` | The project's shared MCP servers (admin to change; a server is named by id or name). `add <name> --endpoint <url>` (not `--url`, which names the Hypotenuse server) with `--header "Name: value"` (repeatable) or `--headers-stdin`, `--bearer-stdin` / `--bearer-env <NAME>`, or `--oauth [--client-id <id> --client-secret-stdin\|--client-secret-env <NAME>]`; the auth mode follows from those flags (or `--auth none\|headers\|bearer\|oauth`), and only one flag may read stdin. Never put a credential on the command line. `--oauth` and `sign-in <server>` print the URL an admin opens to sign the project in (`authorizationUrl` under `--json`). `view <server>` lists its `tools`; `test` / `refresh <server>` reconnect and re-list, exiting 1 when it does not answer (`ok`, `error`). `edit <server>` takes the same flags plus `--name`, `--timeout-ms <ms>` / `--default-timeout`, `--enable` / `--disable`. `match <server> --pattern <p>…` shows what each pattern allows and what still asks (`gated`). `remove <server> --yes` takes it from every bot. Answers carry header names, a bearer's last four, and `signedIn`, never a secret. |
| `hypotenuse conversation create\|message\|list\|view\|cancel\|follow` | Talk to a bot over the API channel. `create --bot <id\|slug> --text <text> [--channel <key>] [--callback-url <url>] [--request-id <id>] [--title <t>] [--follow]` starts one; `message <id> --text <text> [--queue] [--request-id <id>] [--follow]` sends into one (`--queue` waits for the bot's current turn). `--text -` reads standard input. `list [--bot] [--state working\|hibernating\|waiting\|ended]`, `view <id>`, `cancel <id>`. `follow <id> [--since <seq>] [--interval <s>]` prints the transcript and polls until the conversation stops working, then prints its state; it exits 1 when the conversation failed. With `--json`, following prints one JSON object per line: each entry, then `{ conversation }`. A `--request-id` makes a retry safe. |
| `hypotenuse approval list\|view\|approve\|deny` | Tool calls bots wait on. `list [--status pending\|approved\|denied\|expired\|consumed] [--bot <bot>] [--conversation <id>]` (each row says `canDecide`); `view <id>`; `approve <id> [--always] [--note <text>]` runs exactly that call once (`--always` also allowlists its `server/tool` for the bot); `deny <id> [--note <text>]` (the bot reads the note). Deciding needs write access to the bot or its approver tag; it is recorded as decided via `cli`. |
| `hypotenuse large-result view <lr_id> [--offset <n>] [--limit <n>] [--all]` | A tool result too long for the transcript (`lr_<id>` or its number): one page, or `--all` of it; `page.nextOffset` is where the next page starts. Needs read access to the bot. |
| `hypotenuse memory search\|list\|view\|versions\|channels\|write\|forget\|pin\|promote\|reindex` | What bots remember. With neither `--bot <id\|slug>` nor `--channel <channelId>` a command acts on project memory (every bot shares it); with both, on that bot's memory of that channel (`channels --bot <bot>` lists channel ids). `search <query> [--scope project\|channel\|both] [--path <prefix>] [--limit <n>]` ranks as a bot does (`mode` says `hybrid` or `keyword`); `list [--scope …] [--path <prefix>] [--forgotten]` reports each document's `decay` and the `index`; `view <path> [--version-id <id>]` and `versions <path>` read a document and its history. `write <path> --text <text\|-> [--description <d>] [--note <why>] [--base <versionId>]` saves a new version (`--base` refuses it if the document changed since); `forget <path> [--reason <r>]`; `pin <path> [--unpin]`; `promote <path> --bot --channel [--to <path>] [--version-id <id>]` copies channel memory into project memory; `reindex` re-embeds after the embedding model changes. Project memory: members read, admins change; channel memory follows the bot's read and write access; promote and reindex need admin. |
| `hypotenuse audit list [--since 7d] [--until <time>] [--action tag:edit] [--actor-type user] [--target-type tag]` | Who changed what, newest first: the selected project's log (admin), or with `--org` the organization's (owner), narrowed by an explicit `--project`. Times are ISO-8601, epoch ms, or `7d` / `12h` / `30m`. |
| `hypotenuse check-update` | Whether a newer release exists, and its changelog. |
| `hypotenuse upgrade [--major]` | Upgrade by whichever method installed it. A new major version needs `--major`. |
