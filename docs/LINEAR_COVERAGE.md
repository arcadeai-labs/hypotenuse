# Linear coverage

Hypotenuse aims to cover **every** interaction and feature in Linear's agent documentation. This file is the
checklist that makes "every" checkable: one row per documented behaviour, saying where Linear documents it, where
Hypotenuse handles it, which plan builds it, and which test proves it.

It is a **live** document (rule 14 of [`AGENTS.md`](../AGENTS.md)): when a row's handling or test moves, the row
moves in the same commit. `backend/__tests__/docs/linear-coverage.test.ts` parses the tables and fails when:

- an ID is not unique, or a row does not have exactly seven cells;
- a row's status is not one of the values below — there is no `planned`: a row lands with the test that proves it;
- a row names a test file that does not exist, or does not contain the row's ID (in a test name or a `// LC-…`
  comment);
- a `not applicable` row's Handling cell does not say why (it says **not used** or **not needed**, and the test
  asserts the non-use).

[Conformance](./plans/phase-17-conformance-and-e2e.md) is where the matrix became this test.

unused; the Handling cell says why, and the test asserts nothing uses it).

1. Quote Linear's own names (fields, enum values, mutation names) in **Feature**, and link the page in **Source**.
2. Give it the next free ID in its section's prefix (`LC-OAUTH`, `LC-WH`, `LC-SES`, `LC-ACT`, `LC-SIG`, `LC-DEL`,
   `LC-CTX`, `LC-BP`, `LC-AIG`, `LC-RATE`, `LC-DIFF`, `LC-MCP`, `LC-SDK`).

   test enforces it.
