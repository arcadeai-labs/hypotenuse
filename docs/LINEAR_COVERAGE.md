# Linear coverage

Hypotenuse aims to cover **every** interaction and feature in Linear's agent documentation. This file is the
checklist that makes "every" checkable: one row per documented behaviour, saying where Linear documents it, where
Hypotenuse handles it, which plan builds it, and which test proves it.

It is a **live** document (rule 14 of [`AGENTS.md`](../AGENTS.md)): when a row's handling or test moves, the row
moves in the same commit. `backend/__tests__/docs/linear-coverage.test.ts` ([phase 17](./plans/phase-17-conformance-and-e2e.md))
parses the tables and fails when:

- an ID is not unique;
- a row's test file does not exist, or does not contain the row's ID (in a test name or a `// LC-…` comment);
- once the conformance phase is done, any row is still `planned`.

**Status values:** `planned` (not built) · `covered` (handled, test passes against finear) ·
`covered (finear gap)` (handled; the test injects a signed webhook because finear cannot produce the behaviour — see
[Known finear gaps](#known-finear-gaps)) · `not applicable` (deliberately unused, reason in the Handling cell).
Rows marked `planned (not applicable once confirmed)` are expected to become `not applicable` with their reason.

## Known finear gaps

Tests run against [finear](https://github.com/pmdroid/finear), a fake Linear that executes real GraphQL against
Linear's own schema and sends signed webhooks. Where finear cannot produce a documented Linear behaviour, the rule in
[`AGENTS.md`](../AGENTS.md) applies as it does to Keryx: **the gap goes upstream** with a minimal reproduction, and
our test injects a correctly signed webhook built from `@linear/sdk`'s payload types at the HTTP boundary
(`backend/__tests__/linear/inject.ts`) instead of growing a private fake of Linear. Each gap is filed during
[phase 17](./plans/phase-17-conformance-and-e2e.md#finear-upstream-issues); the issue link replaces "to file" when it
exists.

| Gap | Affects rows | Our workaround until fixed | Upstream |
|---|---|---|---|
| Standalone `bun run start` cannot register an OAuth client with a webhook; agent-session webhooks need the in-process `createApplication({ clients })` | all `LC-WH-*` driven by finear | the test harness embeds finear in-process (`backend/__tests__/linear/finear.ts`) | to file |
| An `@`-mention in a comment body does not create a session or send `created` | LC-SES-01, LC-WH-16, LC-CTX-03 | `/__test/agents/mention` control route, plus injected `created` with `previousComments` | to file |
| A human reply in a session thread does not produce `prompted` | LC-WH-13, LC-BP-10 | `/__test/agents/prompt` control route | to file |
